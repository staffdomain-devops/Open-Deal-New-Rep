## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env vars → script | INPUT_LIST_ID and HUBSPOT_API_KEY come from GitHub Actions secrets / workflow dispatch inputs — missing or wrong values must fail loudly, not silently |
| HubSpot API → script | API response is external; shape must be validated before indexing into paging dict |
| script → filesystem | contact_ids.json written to RUNNER_TEMP; a partial write on crash would corrupt the downstream loop |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | HUBSPOT_API_KEY in env | accept | Key sourced from GitHub Actions secrets; never logged; low local exposure risk |
| T-02-02 | Denial of Service | HubSpot 429 rate limit during pagination | mitigate | REQ_RETRY_KWARGS applies exponential backoff + HubSpot ms Retry-After header on every page fetch |
| T-02-03 | Tampering | contact_ids.json partial write on crash | mitigate | Full list built in memory before single json.dump; crash before write leaves no file (downstream loop fails fast on missing file) |
| T-02-04 | Elevation of Privilege | Arbitrary list ID via INPUT_LIST_ID | accept | List IDs are HubSpot list identifiers, not user-controlled in production; CI controls the input |
</threat_model>
