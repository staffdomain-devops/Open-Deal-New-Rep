EMAIL_PROP_NAMES — frozenset of the 10 email property names only (email_1_subject through email_5_body). Used by _bracket_guard to know which properties to scan. task_note_1 and task_note_2 must NOT appear in this frozenset.

FUNCTION: _check_property_schema(client)
  - Iterates over all 12 property names in PROPERTY_MAP
  - For each: calls client.crm.properties.core_api.get_by_name("contacts", prop_name)
  - Checks response.field_type == "textarea"
  - On first mismatch: prints "ERROR: HubSpot property '{prop_name}' has field_type='{actual}', expected 'textarea'. Fix in HubSpot before running write-back." then calls sys.exit(1)
  - On all-pass: prints "Property schema check passed: all 12 properties are textarea."
  - NOT decorated with @retry — a wrong field_type is a config error, not a transient failure; do not retry it

FUNCTION: _bracket_guard(assembled: dict) -> None
  - Iterates over EMAIL_PROP_NAMES only (10 properties); resolves each value from assembled using PROPERTY_MAP key_path
  - If "[" is found in any value: raise ValueError with message "Bracket guard: unresolved placeholder in '{prop_name}' for contact {assembled.get('contact_id')}. Value starts: {value[:80]!r}"
  - task_note_1 and task_note_2 are NOT in EMAIL_PROP_NAMES and must never be scanned

FUNCTION: _build_batch_input(contact_id: str, assembled: dict) -> dict
  - Returns {"id": contact_id, "properties": {prop_name: assembled[top_key][field] for all 12 entries in PROPERTY_MAP}}
  - Returns a plain dict — the caller wraps it in SimplePublicObjectBatchInput

FUNCTION: _write_properties_batch(client, batch_inputs: list) -> None
  - Decorated with @retry(**HS_RETRY_KWARGS) from utils.py
  - Import at top of file: from hubspot.crm.contacts import BatchInputSimplePublicObjectBatchInput, SimplePublicObjectBatchInput
  - Wraps each dict in SimplePublicObjectBatchInput(id=d["id"], properties=d["properties"])
  - Calls client.crm.contacts.batch_api.update(batch_input_simple_public_object_batch_input=BatchInputSimplePublicObjectBatchInput(inputs=inputs))

FUNCTION: main()
  Step 1: Load lint_passing_ids.json from RUNNER_TEMP
  Step 2: write_dlq("batch", "", "startup", "sentinel", 0) — DLQ sentinel written before any contact work (per ERR-02)
  Step 3: client = hubspot.Client.create(access_token=HUBSPOT_API_KEY)
  Step 4: _check_property_schema(client) — sys.exit(1) on failure; no contact loop entered
  Step 5: pending_batch = [], written_count = 0, error_count = 0
  Step 6: Loop over contact_ids:
    a. Load assembled_{cid}.json from RUNNER_TEMP; if file not found: print to stderr and continue (no DLQ write — file absence is a pipeline gap, not a write failure)
    b. Per-contact try/except block:
         _bracket_guard(assembled)
         input_dict = _build_batch_input(str(cid), assembled)
         pending_batch.append(input_dict)
         if len(pending_batch) == BATCH_SIZE:
             _write_properties_batch(client, pending_batch)
             written_count += len(pending_batch)
             pending_batch = []
       except Exception as exc:
         write_dlq(cid, assembled.get("contact_id", str(cid)), "write_properties", str(exc), 0)
         error_count += 1
         print(f"ERROR {cid}: {exc}", file=sys.stderr)
         continue
  Step 7: Flush remaining batch: if pending_batch: _write_properties_batch(client, pending_batch); written_count += len(pending_batch)
  Step 8: print(f"Write-back complete: {written_count} contacts written, {error_count} errors.")

NOTE: _create_note and _pin_note are NOT part of this plan. Plan 06-02 amends main() to add note creation after the properties batch loop.
