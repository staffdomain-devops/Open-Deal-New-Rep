<interfaces>
Script invocation commands (all run from repo root with working-directory: scripts/):
  python fetch_list.py          -- env: INPUT_LIST_ID, HUBSPOT_API_KEY; writes $RUNNER_TEMP/contact_ids.json
  python fetch_record.py        -- env: HUBSPOT_API_KEY; reads contact_ids.json; writes contact_{id}.json per contact
  python exclude_and_route.py   -- reads contact_{id}.json files; writes brief_{id}.json + exclusion_report.json
  python generate_campaign.py   -- env: ANTHROPIC_API_KEY, INPUT_USE_BATCH_API; reads brief_{id}.json; writes generated_{id}.json
  python lint.py                -- reads generated_{id}.json; writes lint_passing_ids.json + review_sample.json
  python assemble_bodies.py     -- reads lint_passing_ids.json + generated_{id}.json; writes assembled_{id}.json
  python assemble_output.py     -- reads lint_passing_ids.json + assembled_{id}.json; writes campaign_output.json
  python write_hubspot.py       -- env: HUBSPOT_API_KEY; reads lint_passing_ids.json + assembled_{id}.json; writes to HubSpot

Intermediate files in $RUNNER_TEMP:
  contact_ids.json              -- written by fetch_list, read by fetch_record
  contact_ids_capped.json       -- written by pilot-mode cap step, replaces contact_ids.json for subsequent steps
  contact_{id}.json             -- per-contact research data
  exclusion_report.json         -- written by exclude_and_route; uploaded as artifact always
  brief_{id}.json               -- per-contact brief
  generated_{id}.json           -- per-contact AI output
  lint_passing_ids.json         -- IDs that passed lint; consumed by assemble_bodies, assemble_output, write_hubspot
  review_sample.json            -- written by lint; uploaded as artifact always
  assembled_{id}.json           -- final assembled content per contact
  campaign_output.json          -- written by assemble_output; uploaded as artifact on success
  failed_contacts.json          -- DLQ file written by utils.write_dlq; uploaded as artifact on failure

Secrets required (CI-06):
  HUBSPOT_API_KEY, ANTHROPIC_API_KEY, TEAMS_WEBHOOK_URL

Teams webhook failure payload fields (ERR-04):
  list_id: the list_id input value
  failed_step: name of the step that failed (from the step name attribute)
  error_excerpt: first 500 chars of the step's stderr/output
  run_url: https://github.com/${{ github.repository }}/actions/runs/${{ github.run_id }}

  <action>
    Create .github/workflows/campaign.yml. Create .github/workflows/ directory first.

    Workflow structure:

    name: Campaign Pipeline

    on:
      workflow_dispatch:
        inputs:
          list_id:
            description: HubSpot list ID to process
            required: true
            type: string
          pilot_mode:
            description: Cap processing at 20 contacts
            required: false
            type: boolean
            default: true

    env block (job-level or top-level):
      INPUT_LIST_ID: ${{ github.event.inputs.list_id }}
      INPUT_USE_BATCH_API: "false"
      HUBSPOT_API_KEY: ${{ secrets.HUBSPOT_API_KEY }}
      ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
      TEAMS_WEBHOOK_URL: ${{ secrets.TEAMS_WEBHOOK_URL }}

    jobs:
      run:
        runs-on: ubuntu-latest
        steps:

        Step: Checkout
          uses: actions/checkout@v4

        Step: Set up Python
          uses: actions/setup-python@v5
          with: python-version: "3.11"

        Step: Install dependencies
          run: pip install -r requirements.txt

        Step: Fetch list (name: fetch-list)
          working-directory: scripts
          run: python fetch_list.py

        Step: Pilot mode cap (name: pilot-mode-cap)
          Inline python -c or shell script that:
          1. Reads $RUNNER_TEMP/contact_ids.json
          2. If pilot_mode input == 'true' AND len(ids) > 20:
             - Slices ids[:20]
             - Writes sliced list back to $RUNNER_TEMP/contact_ids.json
             - Prints "PILOT MODE: capping {original} contacts to 20" to stdout
          3. Always prints "Processing {N} contacts"
          Use: run: python -c "..."
          The inline python reads github.event.inputs.pilot_mode via env var PILOT_MODE.
          Set env: PILOT_MODE: ${{ github.event.inputs.pilot_mode }} on this step.

        Step: Fetch records (name: fetch-records)
          working-directory: scripts
          run: python fetch_record.py

        Step: Exclude and route (name: exclude-and-route)
          working-directory: scripts
          run: python exclude_and_route.py

        Step: Generate campaign (name: generate-campaign)
          working-directory: scripts
          run: python generate_campaign.py

        Step: Lint (name: lint)
          working-directory: scripts
          run: python lint.py

        Step: Assemble bodies (name: assemble-bodies)
          working-directory: scripts
          run: python assemble_bodies.py

        Step: Assemble output (name: assemble-output)
          working-directory: scripts
          run: python assemble_output.py

        Step: Write to HubSpot (name: write-hubspot)
          working-directory: scripts
          run: python write_hubspot.py

        Step: Upload exclusion report (name: upload-exclusion-report)
          uses: actions/upload-artifact@v4
          if: always()
          with:
            name: exclusion-report
            path: ${{ runner.temp }}/exclusion_report.json
            if-no-files-found: warn

        Step: Upload review sample (name: upload-review-sample)
          uses: actions/upload-artifact@v4
          if: always()
          with:
            name: review-sample
            path: ${{ runner.temp }}/review_sample.json
            if-no-files-found: warn

        Step: Upload campaign output (name: upload-campaign-output)
          uses: actions/upload-artifact@v4
          if: success()
          with:
            name: campaign-output
            path: ${{ runner.temp }}/campaign_output.json
            retention-days: 7
            if-no-files-found: warn

        Step: Upload failed contacts (name: upload-failed-contacts)
          uses: actions/upload-artifact@v4
          if: failure()
          with:
            name: failed-contacts
            path: ${{ runner.temp }}/failed_contacts.json
            if-no-files-found: warn

        Step: Upload exclusion report on failure (name: upload-exclusion-report-on-failure)
          uses: actions/upload-artifact@v4
          if: failure()
          with:
            name: exclusion-report-on-failure
            path: ${{ runner.temp }}/exclusion_report.json
            if-no-files-found: warn

        Step: Notify Teams on failure (name: notify-teams)
          if: failure()
          env:
            LIST_ID: ${{ github.event.inputs.list_id }}
            RUN_URL: https://github.com/${{ github.repository }}/actions/runs/${{ github.run_id }}
          run: |
            PAYLOAD=$(python -c "
            import json, os, sys
            list_id = os.environ.get('LIST_ID', 'unknown')
            run_url = os.environ.get('RUN_URL', '')
            payload = {
                'text': f'Campaign pipeline FAILED. list_id={list_id}',
                'list_id': list_id,
                'failed_step': 'see run log',
                'run_url': run_url
            }
            print(json.dumps(payload))
            ")
            curl -s -o /dev/null -w "%{http_code}" \
              -X POST "$TEAMS_WEBHOOK_URL" \
              -H "Content-Type: application/json" \
              -d "$PAYLOAD"

    NOTE on Teams payload: The notify-teams step uses a simple Python inline to build the JSON
    payload. The fields must include list_id, failed_step (set to "see run log" since GitHub
    Actions does not expose which step failed natively), run_url, and a human-readable text field.
    This satisfies ERR-04. If TEAMS_WEBHOOK_URL is empty (not configured), curl exits non-zero
    but the workflow is already in failure state so this is acceptable.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| workflow_dispatch inputs to env | list_id and pilot_mode enter as user-supplied strings from GitHub UI |
| env secrets to scripts | HUBSPOT_API_KEY, ANTHROPIC_API_KEY, TEAMS_WEBHOOK_URL flow from GitHub Secrets |
| RUNNER_TEMP files | Written and read within the same job; trusted — no cross-job sharing |
| Teams webhook POST body | Constructed from github context values; no user-supplied data echoed into the payload |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-02-01 | Spoofing | workflow_dispatch list_id input | accept | Only GitHub users with Actions write permission can trigger; list_id is passed as-is to HubSpot API which validates it |
| T-07-02-02 | Information Disclosure | Teams webhook payload | mitigate | Payload contains only list_id (not PII), run URL, and generic failure text; no contact data or secrets echoed |
| T-07-02-03 | Information Disclosure | Artifact contents | mitigate | Artifacts are scoped to the repository; access requires GitHub write permission; no additional controls needed for v1 |
| T-07-02-04 | Tampering | contact_ids.json overwrite by pilot-mode step | accept | Overwrite is intentional and within the same trusted job; no external input influences the slice logic beyond contact count |
| T-07-02-05 | Denial of Service | Teams webhook failure blocking job cleanup | accept | notify-teams step runs in failure context; if curl fails, job is already failed; no cascading impact |
</threat_model>
